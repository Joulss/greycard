# §616. The window in other languages

*2026-11-08*

Issue 75 asks for the window in other languages, with French offered.
We promised it for the release after 0.10.0, so 0.11.0 waits for the
foundation: every string of the window translatable, a catalog for
translators, and a language picker. It ships English alone; the first
translations come as pull requests against the catalog.

**Where the strings are.** About 240 in the Slint files (`text`,
`words`, `placeholder-text`, `accessible-label`), a few hundred set
from Rust (status words, menus, sheets, the keys table's help, error
text), 81 of those format strings with values. Logs stay English, as
do the guide and the release notes. Tests assert on English wording
and keep doing so: English is the source language and a test sets no
language.

**Slint's side.** Every shown string becomes `@tr("...")`, with
`@tr("{} of {}", a, b)` for values and `@tr("{n} frame" | "{n} frames"
% n)` for plurals. `build.rs` bundles the catalogs
(`with_bundled_translations`) with no default context, so one string
is one entry wherever it appears; the window picks the language with
`select_bundled_translation` after its first component exists. No
gettext library at runtime on any platform.

**Rust's side.** A `tr!` macro of our own in greycard-ui, the
`tr` crate's shape: `tr!("Exporting {} of {}", n, total)`, named
`{name}` placeholders so a translator may reorder, and
`tr!("{n} frame" | "{n} frames" % n)` with the catalog's plural rule.
It reads the same catalogs, parsed by pure Rust at build time into
static tables; no C library, no file at runtime. Tables of
`&'static str` (the keys table, the status words, the section names)
stay English constants and are translated where they are shown, never
where they are compared or stored.

**One catalog.** `translations/<lang>/LC_MESSAGES/greycard.po`, both
sides' strings in it, generated by `scripts/translations.sh`:
`slint-tr-extractor` over the Slint files and `xtr` over the Rust,
merged into `translations/greycard.pot`, and each language's `.po`
updated from it. A translator edits one file. If Slint's domain cannot
be renamed from the crate's name, the Slint catalog keeps its own file
beside and the script writes both from the one `.pot`; the design
prefers the single file.

**The picker.** Settings > Interface gains a row "Language": "System"
first, then every language the catalogs hold, each in its own name
("Français"). Kept in settings.json as a BCP 47 tag or empty for
System. System reads the platform's locale (`sys-locale`), takes the
language part, and falls to English when no catalog matches. A change
applies on the next start; the row says so under it with the text
"Takes effect when greycard next starts". The guide and the keys sheet
show the language's words where the window does.

**Kept honest.** A test in greycard-slint scans the Slint files for a
bare `text:`, `words:`, `placeholder-text:`, or `accessible-label:`
string literal and fails on one, with an allow-list for the few that
are data (a glyph, a key name). CI runs it with the rest. A reviewer
reading a Rust diff looks for a shown string outside `tr!`. The
translators' page, `docs/translating.md`, says how to add a language
and how plurals and placeholders work.

**Not in this section.** Dates, numbers, and units follow the window's
language in a later section; a right-to-left layout; translating the
guide; a hosted Weblate, which comes when the queue of translators
asks for one. The wording of the English source is tidied before the
first translation starts, since a changed English line unsettles every
translation of it; the tidy is its own section.

**What changes for a user.** Nothing until a language is picked or
the system's is one we carry. The builds carry the catalogs, so a
language is a file in the repository, never a download.

## What was built

**The foundation**, with no existing string wrapped yet: the catalogs,
both sides' lookup, the Language setting, the scan, and the script.

**One catalog, one domain.** slint-build takes the translation domain
from `CARGO_PKG_NAME` and offers no setter, so greycard-slint's build
script sets that variable to "greycard" for its own process before any
thread starts (a `with_translation_domain` setter on our Slint fork
would be the cleaner way, and is the route when the fork is next
touched). Slint then bundles
`translations/<lang>/LC_MESSAGES/greycard.po`, the same file the Rust
side reads: the single file the design preferred. No default context.

**Rust's `tr!`.** `greycard_ui::tr!` in `crates/greycard-ui/src/i18n.rs`,
the `tr` crate's shape so `xtr` extracts it: `tr!("s")`,
`tr!("{} of {}", a, b)`, `tr!("{done} of {total}", done = d, total = t)`
(also `{0}`, `{1}`), and `tr!("{n} frame" | "{n} frames" % n)`. It
always returns a `String`. greycard-ui's build script reads every
catalog with a small pure-Rust `.po` reader (`i18n/po.rs`) into static
tables (fuzzy and empty entries left out; a byte-order mark and C's
escapes, octal and hex among them, read); the plural rule is
`i18n/plural.rs`, gettext's C subset, checked at build time and
evaluated at runtime. A catalog or rule that will not read fails the
build. Nothing is read from disk at runtime; no gettext library.

**The setting.** `Settings.language` in greycard-ui's settings.rs (not
the engine's `Shared`, which the headless runs read and which has no
use for it): a tag or empty for System, read leniently, kept through
the close like the theme. At start, after `App::new` and before the
window shows, `prefs::start_language` resolves System through
`sys-locale`, picks the whole tag's catalog, else its language part's,
else English, and selects it on both sides. A setting no catalog
matches falls to the system's languages, `sys_locale::get_locales()`
in order, the first with a catalog. A script subtag is dropped, and
`zh-Hant` and `zh-Hans` with no region take `zh_TW` and `zh_CN`. Slint picks the system's
language for its bundle on its own at the first component; the start
always overrides it, and the tests' window selects English, so a test
on a French machine still reads English.

**The picker.** Settings > Interface > Language, a ComboBox: System,
then each catalog's language in its own name (a small table keyed by
tag, the tag itself for one not in it), at the place of the setting's
catalog (`fr-CA` at French; a setting with none at System). Slint has no way to put a
string ahead of a model, so "System" is `@tr` in a global,
`LanguageWords.system`, which the Rust side reads to build the list.
Under the row: "Takes effect when greycard next starts", always shown.

**Proving the Slint side.** `crates/greycard-i18n-probe`, a
workspace member with `publish = false`: one component with a `@tr`
string and a plural, built the way greycard-slint is (the domain set,
no default context) over a French catalog of its own. Its test selects
"fr", reads the translation and French's plural through properties,
selects "" and reads English. It runs under either profile, and no
translator's edit reaches it. The window's builds bundle the
repository's catalogs alone, debug or release.

**The scan.** `crates/greycard-slint/tests/untranslated.rs` walks
`ui/**/*.slint` for a string literal outside `@tr(...)` in a shown
binding: `text`, `words`, `placeholder-text`, `placeholder`,
`accessible-label`, `accessible-description`, `title`, `label`,
`note`, `hint`, `tooltip`, `tips`, `empty`, `labels`, and `options`.
Comments are skipped, and an expression is followed to its `;`, to the
`,` that ends a struct literal's field, or to its element's `}`. A
`Segmented`'s `options` are shown and also compared, so they count as
bare until the element binds its shown words as `labels`, and the
report marks them. The allow-list, `ui/untranslated.txt`, holds the
data strings in quotes (glyphs, punctuation, numbers, units' symbols,
file formats, the program's name). It reports `file:line: "text"`;
1054 offenders before the allow-list's data strings, 912 after
(the count the wrapping starts from).
Landed `#[ignore]`d; the wrapping un-ignores it. A test of the scanner
itself runs now.

**The script.** `scripts/translations.sh`: slint-tr-extractor (no
default context) over the Slint files, xtr over the library and the
binary, msgcat into `translations/greycard.pot` under our header,
msgmerge into each language. The tests of `tr!` call it by another
name so xtr does not take their strings. The committed `.pot` and
French `.po` are header only.

`tr!("...")` with no values goes through the same fill as one with
values, so `{{` is a brace either way.

*Verified.*

- `tr!` unit tests: lookup, fuzzy and empty fallback, context keys,
  multi-line strings and escapes, named and indexed placeholders
  reordered by a translation, plurals by French's and English's rules,
  gettext's Russian, Polish, Czech, and one-form rules, bad rules
  refused, tag picking (`fr-CA`, `fr_FR.UTF-8`, `pt-BR`, none).
- greycard-i18n-probe: French selected, the translation and French's
  plural read through properties; English again; an unbundled language
  refused.
- The window's bundle holds French: selected, the row lists it at its
  place; English selects again.
- A second build in a row leaves greycard-slint fresh.
- The Language row lists System and Français; index 1 is "fr", System

- `language` reads leniently and round-trips through settings.json
  (`change_at`, `load_from`).
- The scanner finds the bare strings of a test source by line; run
  `--ignored` over the real files it lists the window's offenders.
- `scripts/translations.sh` ran with the extractors installed under

  and the French catalog was merged.

*Not verified.*

  under test, so the row's write is checked through `language_chosen`
  and the file round trip, not through a click.
- The ComboBox's popup clicked, and the row's look on screen.
- A start with a French system locale, end to end, on any platform;
  `sys-locale` on Windows and macOS.
- The scan's heuristics on every pattern the wrapping will meet, and
  `element_binds`' look for `labels` beside an `options`.
- A Hant or Hans locale on a real system.

### The Slint files wrapped

**Every shown string in the Slint files is in `@tr`.** 901 `@tr`
calls where there were 4, over 48 files. A plain string became
`@tr("...")`; a sentence built with `+` became one format string,
`@tr("Remove {} from the list?", name)`, so a translator may move the
value; a count became a plural, `@tr("Move {n} reject..." | "Move {n}
rejects..." % n)`, including the ones English only shows for two or
more ("Export {n} frames"), since other languages' plural rules pick a
singular form at 21. The English a reader sees is unchanged, word for
word, with one exception in principle: a thumbnail's spoken rating now
takes its plural from the stars counted, not the rating, which differs
only if `meta::STARS` were 1.

**Shown and compared, kept apart.** `Segmented` gained `labels`, the
shown words by index; `options` stay the English values the host and
`current` compare. 36 rows bind labels; a row whose options are all
data (color spaces, formats) needs none. The same split, by other
means, where a value is shown:
- the crop's aspect ComboBox shows translated names and keeps the
  English name by index (`current-index` both ways, through the
  existing `changed aspect-name`);
- the settings categories show `category-words` by index;
- the watermark's place and the border's color, shown under their
  pickers, go through `position-words` and `border-words`;
- the learned denoise row's "off", which this side adds, has a label;
  the tiers' names from Rust are shown as they are.

**Values stay bare.** A string handed to a callback (`add-part("Face")`,
`add-shape("Sky")`, `pick-started(...)`) is a key, never wrapped.

**Not only the scanned bindings.** Words in properties the scan does
not read were wrapped by hand: the preset, noise, and detail word
globals, the label menu's names, the grade wheels' names, the
history's Reset action, a root's spoken value, the key field's "Press
a key", the sidecar counts, the proof badge, the status line's
"preparing...", the canvas names, and the window's defaults for
words Rust sets later (zoom, sheet verbs, fetch answers).

**The scan.** Un-ignored, so `cargo test -p greycard-slint` runs it,
and it passes at 0. Three fixes found on the way, and a test that a compared operand
exempts only itself: `mode == "a" ? "Shown" : "Other"` still reports
both branches: an element's id
(`hint := Text`) and a property read in an `if` (`root.placeholder:
Rectangle`) were taken for bindings, and a value compared (`mode ==
"Copy"`) for a shown one. Each has a line in the scanner's own test.

**Spoken values.** `accessible-value` is a shown binding in the scan
now. The Segmented rows whose labels are words (Monitor, Soft proof,
its intent, Fill, Format, and the retouch Fill row) speak the label,
not the English value, by a ternary at each row.

**The allow-list** grew by 17 data strings to 65: glyphs written as
escapes (`\u{00b0}`, `\u{2030}`, `\u{00d7}`, the owner's dot), the
mired unit, the hint keys C and S, `+JPEG` and `RAW+JPEG`, the
placeholders `{name}`, `W:H`, and the time shift's example, and the
color spaces and AgX as Segmented labels. The import sheet's name
tokens, `{date} {yyyy} ...`, go in as an argument to their sentence,
so no translator sees them as words to change.

**The catalog.** `scripts/translations.sh` over the result: 645
messages in `translations/greycard.pot`, every one from a Slint file
(the Rust side's `tr!` strings come with the Rust wrapping), no
context, no duplicate (msguniq -d finds none), no test string. The
French catalog merged, all untranslated.

*Verified.*

- The scan over the real files: 0 bare strings; its own test with
  the new cases.
- `cargo test -p greycard-slint -p greycard-ui` on lavapipe: all pass
  (the scan's 2, the library's 178, the binary's 1414 with 5 ignored,
  the export tests' 3). The first run found two source-text tests
  reading the mask panel for bare words, and with them a real slip:
  the parts menu's callback was handed `@tr("Face")`, a translated
  key the Rust side looks up by English label. The key is bare again;
  the two tests now look for `@tr(...)`.
- fmt; clippy --all-targets -D warnings on greycard-slint and
  greycard-ui.
- The `.pot` and the French `.po` regenerated: 645 messages, no
  msgctxt, no duplicate, French's plural header kept.

*Not verified.*

- A translated window: no catalog has a translation yet, so no
  `@tr` has been seen to change; the probe crate stands for it.
- Each changed sentence read on screen: the tests that assert a
  shown string cover many, not all; the rest are checked by reading
  the diff.
- The aspect box after a pick on screen (the index round trip is
  exercised only through the tests that set `aspect-name`).
- Strings Rust sets and Slint compares or shows (mask kinds, the
  archive verbs, the rawtherapee rows' "frame" label, the denoise
  tiers, the lens makers' "All", match scopes): the Rust wrapping's.
