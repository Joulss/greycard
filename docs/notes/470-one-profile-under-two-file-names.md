# §470. One profile under two file names

*2026-10-31*

A tester's profile folder held Adobe Standard for an EOS 850D twice:
once under the body's own name and once under its US name, the Rebel
T8i, the same bytes. Each file carries the profile's name inside and
names the body as Adobe does, so since §423 both fit the 850D, and
the CAMERA PROFILE list showed each by its inner name: two rows
reading Adobe Standard, nothing to tell them apart (discussion 59).

**Pairs fold in the store.** The listing reads headers alone, as it
did; where two entries share a camera and a profile name it stats
them, and reads bytes only where the lengths agree, each file once.
Identical files are one profile: the file whose stem names the
profile stands for the pair, else the first by name, and the others
point at it. Every file stays an entry, so a sidecar naming either
loads it, and the warning, the sync, the preset check, and the
import keep working by name. A folder of unrelated profiles pays no
extra read.

**Twins are told apart at the panel.** Over the rows that fit the
body, any label repeated gets its file name in parentheses, Adobe
Standard (Canon EOS Rebel T8i). That covers two different files
naming the body by its two names, which never group in the store,
since the store has no body in hand. A file the edit chose that is
a pair's copy takes the pair's place in the rows, so the panel still
selects what the sidecar says.
